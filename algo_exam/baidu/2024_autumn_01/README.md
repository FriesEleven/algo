## q01 时钟指针

[题目链接](https://www.nowcoder.com/questionTerminal/c6abd4fff1c04175b6c78cbcb4778ff9)

### 1. 题意转化

日期不可见，但记录已经按真实时间先后排列。对于两个相邻记录，只需在所有可能的日期差中，找出与两个钟面读数相符的最短非负时间差，再换算成秒针转过的圈数。

把一个时刻换算为当天第几秒：

    value = hh × 3600 + mm × 60 + ss

一天共有 86400 秒。设前后两个钟面值分别为 current、next，则最短时间差是：

    delta = (next - current + 86400) mod 86400

当 next 不小于 current 时，这就是同一天的差；当 next 小于 current 时，加一天表示跨过零点；当二者相等时，最小差为 0。

### 2. 为什么公式正确

所有可能的真实时间差都满足：

    elapsed = next - current + d × 86400

其中 d 是非负的跨日数，并且 elapsed 不能为负。对 86400 取模后，所有候选都落在同一个余数类中。公式取到的是区间 [0,86400) 内唯一的代表，因此正好是最小非负候选；再多跨一天只会让时间差增加 86400 秒，不可能更优。

秒针 60 秒转一圈，所以圈数为：

    turns = delta / 60.0

这里是实数除法，因为 30 秒对应 0.5 圈，并不要求只统计完整圈数。

### 3. 示例演算

相邻记录为 23:59:50 和 00:00:20：

    current = 23×3600 + 59×60 + 50 = 86390
    next    = 20
    delta   = (20 - 86390 + 86400) mod 86400 = 30
    turns   = 30 / 60 = 0.5

若记录为 12:00:00 和 12:01:30，则 delta=90，秒针转 1.5 圈。

### 4. 算法步骤

1. 读取第一个时刻并换算为秒数，记为 current。
2. 依次读取后续时刻，换算为 next。
3. 用环形差公式计算 delta，输出 delta/60.0。
4. 令 current=next，继续处理下一对。

### 5. 边界与实现注意

- 时间字符串固定为 hh:mm:ss，可以按固定位置解析，也可以按冒号切分。
- 两个钟面值相同时，题目要求“至少”，因此答案是 0，而不是强制认为经过了一整天。
- 输出允许误差，使用 float64 计算并输出足够的小数位。
- delta 最大为 86399，整数本身不会溢出。

### 6. 复杂度

- 时间复杂度：O(n)，每个记录只解析一次。
- 额外空间复杂度：O(1)，只保留前一个时刻。

## q02 数学题

[题目链接](https://www.nowcoder.com/questionTerminal/23c6e322754946aa9687db77688b5206)

### 1. 题意转化

每组询问都比较：

    a op b    与    b op a

直接计算乘法或乘方可能溢出，但五种运算可以按代数性质分类，不需要得到实际结果。

### 2. 分运算符推导

#### 加法和乘法

二者满足交换律：

    a+b = b+a
    a×b = b×a

所以答案恒为等号。

#### 减法

两边作差：

    (a-b) - (b-a) = 2(a-b)

系数 2 为正，因此结果大小只由 a 与 b 的大小决定。

#### 除法

a、b 都是正数，可以安全地同乘正数 ab：

    a/b ? b/a
    a²  ? b²

正数平方保持大小关系，所以仍然只需比较 a 与 b。即使语言中的题目实现按整数除法理解，正整数下 a>b 时 a/b≥1、b/a=0，结论也相同。

#### 乘方

不能构造 a^b。对正数取自然对数不会改变大小关系：

    a^b ? b^a
    b×ln(a) ? a×ln(b)

正整数中，精确相等只会出现在 a=b，或无序数对 {a,b}={2,4}。先显式处理这些相等情况，其余情况用 long double 比较两个对数值，可避免整数幂溢出，也避免用过大的误差把严格不等误判为相等。

### 3. 正确性说明

前四类结论都来自等价变形，变形过程中只做了两边同减或同乘正数，不会改变比较符号。乘方使用的是严格单调的对数函数，因此比较对数与比较原幂完全等价；单独处理全部整数相等解后，剩余结果必为严格大于或严格小于。

### 4. 示例演算

- a=3、b=2、op 为减法：3-2=1，2-3=-1，所以左边大；直接比较 3>2 得到相同结论。
- a=2、b=4、op 为乘方：2^4=16，4^2=16，命中特殊相等对。
- a=3、b=2、op 为乘方：2×ln3 大于 3×ln2，对应 3²=9 大于 2³=8。

### 5. 算法步骤

1. 若 op 是加法或乘法，输出等号。
2. 若 op 是减法或除法，比较 a 与 b。
3. 若 op 是乘方：
   - a=b 或 {a,b}={2,4} 时输出等号；
   - 否则比较 b×ln(a) 与 a×ln(b)。

### 6. 边界与实现注意

- a、b 可达 10^9，乘方绝不能直接计算。
- a=1 或 b=1 时 ln(1)=0，公式仍成立。
- Go 只有 float64；其精度足以区分本题非相等整数对。实现时先做精确相等分类，不依赖宽松 epsilon 判等。
- 加减乘除分支完全可以只使用整数比较。

### 7. 复杂度

- 时间复杂度：每组 O(1)，总计 O(t)。
- 空间复杂度：O(1)。

## q03 流言终结者

[题目链接](https://www.nowcoder.com/questionTerminal/6a9b2fd27bbf4291aea47669aeea6311)

### 1. 题意转化

第一种人听到流言后会继续向所有未听过的朋友传播；第二种人听到后立即停止。于是传播路径有一个重要限制：

- 路径的中间节点只能是第一种人；
- 第二种人可以成为最终接收者，但不能把路径继续延长。

因此，若起点是第一种人，传播范围由“第一种人诱导子图中的连通块”决定；若起点是第二种人，传播范围只有自己。

### 2. 连通块答案如何组成

只保留两端都是第一种人的边。对某个连通块 C：

1. C 中所有第一种人都会互相传播到；
2. 与 C 中任一点相邻的第二种人都会听到；
3. 这些第二种人不会继续传播；
4. 同一个第二种人即使与 C 有多条边，也只能计一次。

所以预处理值为：

    answer(C)
    = C 内第一种人的数量
    + 与 C 相邻的不同第二种人的数量

### 3. 如何去重边界上的第二种人

用并查集合并第一种人之间的边后，枚举每条“一种人—二种人”边，生成二元组：

    (第一种人所在块的根, 第二种人编号)

将全部二元组排序并去重。每个不同二元组只给对应连通块加一，恰好消除同一第二种人与同一块之间的重复边，同时允许它分别成为多个不同连通块的边界节点。

### 4. 正确性说明

从第一种起点出发，沿第一种人组成的路径可以到达且只能到达其并查集连通块；到达块内任一节点后，流言会沿所有出边传给相邻第二种人。因为第二种人不再传播，不可能到达边界以外的新节点。因此上述“块内节点 + 不同边界二种人”既没有遗漏，也没有多计。

若起点本身是第二种人，它不会执行任何传播动作，所以答案固定为 1。

### 5. 示例演算

设 1、2 是第一种人，3、4 是第二种人，边为：

    1-2, 1-3, 2-3, 2-4

第一种人连通块为 {1,2}。边界第二种人集合为 {3,4}，虽然 3 有两条相邻边，去重后仍只计一次：

    answer({1,2}) = 2 + 2 = 4

从 1 或 2 发起时答案都是 4；从 3 发起时答案是 1。

### 6. 算法步骤

1. 建立并查集，只合并两端均为第一种人的朋友边。
2. 统计每个根下第一种人的数量。
3. 枚举跨类型边，生成“根—第二种人”二元组。
4. 排序、去重二元组，统计每个根的不同边界人数。
5. 对每个查询：
   - 起点是第二种人时输出 1；
   - 否则输出其根的块内人数与边界人数之和。

### 7. 边界与实现注意

- 无向边可能以任意端点顺序输入，处理跨类型边时要先判断哪端是第一种人。
- 并查集查询要做路径压缩；计数应在所有合并完成后按最终根汇总。
- 二元组排序可编码为结构体，也可编码成 64 位整数。
- 答案不超过 n，普通整数足够；边数和查询数较大，输入需要缓冲。

### 8. 复杂度

- 并查集合并与查询：O((n+m+q) α(n))。
- 二元组排序：O(m log m)。
- 总时间复杂度：O((n+m+q) α(n)+m log m)。
- 空间复杂度：O(n+m)。
