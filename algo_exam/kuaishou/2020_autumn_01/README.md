# 2020 Autumn 01 算法题思路

本文只整理算法推导与实现要点，不包含完整代码或输入输出模板。

## q01：病毒检测

题目链接：[病毒检测](https://www.nowcoder.com/questionTerminal/6f0d16fc06274f44af8913d182668037)

### 题意转化与关键观察

要求统计连续子串中字符 `'1'` 的个数恰好为 `k` 的位置区间数。把 `'1'` 视为 `1`、`'0'` 视为 `0`，问题就变成“有多少个子数组的和等于 `k`”。二进制前缀和单调且范围只在 `0..n`，可以用频次数组在线计数。

### 从定义到计数公式

令 `pre[i]` 为前 `i` 个字符中 `'1'` 的数量，`pre[0]=0`。子串 `(l+1..r)` 中的 `'1'` 数量为

\[
pre[r]-pre[l]。
\]

它等于 `k` 当且仅当 `pre[l]=pre[r]-k`。因此扫描到右端点 `r` 时，只需知道此前有多少个前缀值等于 `pre[r]-k`，这个数量就是以 `r` 结尾的新合法子串数。

维护 `freq[x]` 表示已经扫描过的前缀和 `x` 出现次数。初始空前缀使 `freq[0]=1`；每读一个字符，先更新当前前缀和，再把 `freq[sum-k]` 加入答案，最后执行 `freq[sum]++`。

### 正确性说明

每个子串唯一对应一对前缀下标 `(l,r)`。算法在处理其右端点 `r` 时，恰好通过前缀值 `pre[r]-k` 统计到左端点前的 `l`；不同的 `l` 分别计数。反之，频次数组中的每个被统计前缀都满足差为 `k`，必然对应一个合法连续子串。因此没有遗漏也没有重复。

### 示例演算：`s=0101, k=1`

前缀和依次为 `0,0,1,1,2`。

- 扫到第一个 `1` 时当前和为 `1`，此前前缀和 `0` 出现 2 次，新增 2 个子串。
- 再扫过一个 `0`，当前和仍为 `1`，又新增 2 个。
- 扫到最后一个 `1` 时当前和为 `2`，此前前缀和 `1` 出现 2 次，再新增 2 个。

答案为 `6`。

### 算法步骤

1. 建立长度至多 `n+1` 的频次数组并清零。
2. 设 `freq[0]=1`、`sum=0`、`ans=0`。
3. 从左到右扫描字符；遇到 `'1'` 就令 `sum++`。
4. 若 `sum>=k`，令 `ans+=freq[sum-k]`。
5. 执行 `freq[sum]++`，继续扫描。
6. 输出 `ans`。

### 实现注意

- 必须“先查询、后加入当前前缀”。尤其 `k=0` 时，反过来会把长度为 0 的空子串计入答案。
- `k` 大于整串 `'1'` 总数时答案自然为 `0`，无需特判。
- 长度可达 `10^6`，答案最大约为 `n(n+1)/2`，使用 64 位整数；前缀频次本身用整数即可。
- 32 MB 限制下，`n+1` 个整型频次约占 4 MB，方案可行。

### 复杂度

- 时间复杂度：`O(n)`，每个字符只处理一次。
- 空间复杂度：`O(n)`；也可按 `'1'` 的实际总数开数组。

## q02：考试成绩

题目链接：[考试成绩](https://www.nowcoder.com/questionTerminal/65429b39865a4d4a8fd11ea1c7bcb7ce)

### 题意转化与关键观察

可以“乐观地”决定每一道题的正确选项，使全班总分最大。第 `j` 题选什么答案不会影响其他题，因此总目标可以拆成 `m` 个完全独立的单题最优化。

### 从单题贡献到公式

设第 `j` 题选择 `A..E` 的人数分别为 `cnt[j][0..4]`，该题分值为 `score[j]`。若把选项 `c` 设为正确答案，该题给全班带来的总分就是

\[
cnt[j][c]\times score[j]。
\]

由于分值固定且非负，人数最多的选项贡献最大，所以第 `j` 题最优贡献为

\[
\max_c cnt[j][c]\times score[j]。
\]

对所有题求和即可。

### 正确性说明

任意一套答案的总分都是各题贡献之和，而题与题之间没有共享限制。若某题没有选择人数最多的选项，把该题答案单独改为人数最多的选项只会提高或保持总分，也不会影响其他题。逐题执行这个交换后得到算法方案，因此算法达到全局最优。

### 示例演算

某题 3 名学生分别回答 `A、B、A`，该题 10 分。选 `A` 时有 2 人答对，贡献 `20`；选 `B` 只有 `10`，其余选项为 `0`，所以这题应贡献 `20`。若另一题最优贡献为 `12`，全班最优总分就是 `20+12=32`。

### 算法步骤

1. 建立 `m*5` 的计数表并清零。
2. 读取每名学生的答案串；对每个位置 `j`，执行 `cnt[j][answer-'A']++`。
3. 对每道题 `j` 求五个计数的最大值 `best`。
4. 把 `best*score[j]` 累加到 64 位答案。
5. 输出总和。

### 实现注意

- 选项字符只在 `A..E`，可直接映射到 `0..4`。
- 并列最多的选项任选，所得分数相同，不需要记录具体答案。
- 注意原题中每道题分值的读取位置；本文件不重复 IO 格式。
- 即使单题人数不大，分值和题数叠加后总分应使用 64 位整数。

### 复杂度

- 时间复杂度：`O(nm)`；`n,m<=1000`，最多处理 `10^6` 个答案字符。
- 空间复杂度：`O(5m)=O(m)`。

## q03：石头碰撞

题目链接：[石头碰撞](https://www.nowcoder.com/questionTerminal/9dd19c9305704138bdf83e2dffdcb4f4)

### 题意转化与关键观察

一次碰撞把 `x,y` 变成 `|x-y|`。不断展开这些绝对差，最终剩余重量可写成所有原石头重量分别取正号或负号后的绝对值，即

\[
|\sum_{i\in A}w_i-\sum_{i\in B}w_i|。
\]

因此目标是把石头分成两组，使两组重量和尽量接近。这是总重量较小的 0/1 背包。

### 从分组到背包状态

设总重量为 `S`，一组重量为 `x`，另一组就是 `S-x`，最终差为 `|S-2x|`。交换两组不改变答案，所以只需寻找 `x<=S/2` 时最大的可达子集和 `best`，答案为

\[
S-2\times best。
\]

可以令 `reachable[j]` 表示是否能从已处理石头中选出总重 `j`。初始仅 `reachable[0]=true`；处理重量 `w` 时从 `S/2` 向 `w` 倒序更新 `reachable[j] |= reachable[j-w]`。

### 正确性说明

每次差碰撞只会给参与表达式的两部分赋相反符号，因此任何碰撞结果都对应某个正负分组；其重量至少是最优分组差。反过来，经典的差碰撞可以按两组归并并相互抵消，实现该分组的差值，所以最小结果就是所有分组差的最小值。背包枚举了每个石头选或不选，得到不超过一半的最大组和，恰好使差最小。

### 示例演算

石头为 `[2,7,4,1,8,1]`，总和 `S=23`，容量为 `11`。背包可达到 `best=11`，例如选出 `7+4`；另一组和为 `12`，最终最小剩余重量是 `23-2*11=1`。

### 算法步骤

1. 求所有重量总和 `S`，令容量 `cap=S/2`。
2. 初始化布尔数组，只有 `reachable[0]=true`。
3. 对每块重量 `w`，令 `j` 从 `cap` 递减到 `w`，更新可达性。
4. 从 `cap` 向下找到第一个可达的 `best`。
5. 输出 `S-2*best`。

### 实现注意

- 容量必须倒序枚举，否则一块石头会在同一轮被重复选取，变成完全背包。
- 两组相等时答案为 `0`，表示最后两块等重石头可一起消失。
- `n<=100`、`S<=10000`，用布尔数组即可；也可用 bitset 左移优化，但不是必需。

### 复杂度

- 时间复杂度：`O(nS)`，上界约 `10^6` 次状态更新。
- 空间复杂度：`O(S)`。

## q04：蓄水池大作战

题目链接：[蓄水池大作战](https://www.nowcoder.com/questionTerminal/ce77ba1ab9aa4b18b31158972705cf75)

### 题意转化与关键观察

题目约定每条输入边中编号较小的节点是编号较大节点的父节点。因此可以把无向连接拆成两个有向邻接表：`down[u]` 保存直接儿子，`up[u]` 保存直接父亲。

操作 1 会修改 `v` 以及沿 `down` 可达的全部后代；操作 2 会修改 `v` 以及沿 `up` 可达的全部祖先；操作 3 只查询单点状态。由于 `n,q<=1000`，每次直接遍历受影响节点已经足够，无需复杂的树上数据结构。

### 从操作定义到状态维护

维护 `water[u]`：`1` 表示有水，`0` 表示空。

- 填水 `(1,v)`：从 `v` 做 DFS/BFS，每沿父到子边扩展一次，把访问节点设为 `1`。
- 清空 `(2,v)`：从 `v` 做 DFS/BFS，每沿子到父边扩展一次，把访问节点设为 `0`。
- 查询 `(3,v)`：输出当前 `water[v]`。

编号沿 `down` 严格增大、沿 `up` 严格减小，不会形成有向环；底层仍可准备访问标记，使实现更稳健。

### 正确性说明

根据定义，`v` 的所有后代恰好是从 `v` 沿 `down` 可达的节点，填水遍历访问且只访问这个集合；祖先与 `up` 同理。每次操作把目标集合内所有状态覆盖成指定值，集合外不改动，所以执行后的 `water` 与题意完全一致。查询直接读取维护状态，因而正确。

### 示例演算：操作过程

设方向边为 `1->2、1->3、3->4`，初始均为空。

1. 填满 `3`：节点 `3,4` 变为有水，状态为 `[0,0,1,1]`。
2. 填满 `2`：节点 `2` 有水，状态为 `[0,1,1,1]`。
3. 清空 `4`：沿祖先方向访问 `4,3,1`，它们清空；节点 `2` 不在祖先集合中，仍有水。

### 算法步骤

1. 对每条边 `(a,b)`，先令 `parent=min(a,b)`、`child=max(a,b)`。
2. 加入 `down[parent].push(child)` 和 `up[child].push(parent)`。
3. 初始化全部 `water[u]=0`。
4. 遇到操作 1，从 `v` 沿 `down` 迭代遍历并赋值 `1`。
5. 遇到操作 2，从 `v` 沿 `up` 迭代遍历并赋值 `0`。
6. 遇到操作 3，输出 `water[v]`。

### 实现注意

- 两类修改都包含起点 `v` 本身。
- 不能随意选根后重新定义父子；必须使用题面“小编号为父”的约定。
- 多次填水或清空同一节点没有问题，操作是覆盖而非翻转。
- 深度最多 `n`，递归通常也能通过，但迭代栈/BFS 可避免栈限制差异。

### 复杂度

- 建图时间、空间均为 `O(n)`。
- 单次修改最坏访问 `O(n)` 个节点，查询 `O(1)`；总时间最坏 `O(nq)`，`n,q<=1000` 时约 `10^6` 级别。
- 额外空间复杂度：`O(n)`。
