# 2020 Autumn 02 算法题思路

本文只整理算法推导与实现要点，不包含完整代码或输入输出模板。

## q01：运动会

题目链接：[运动会](https://www.nowcoder.com/questionTerminal/ef5361a45d9c42b79ff01744c7d1b3ff)

### 题意转化与关键观察

项目 `i` 的持续时间为 `d_i=end_i-start_i`。参加时长必须是整数且严格超过一半，所以最少需要

\[
need_i=\lfloor d_i/2\rfloor+1
\]

个连续小时。每个项目只能参加一次、同一时刻不能参加多个项目，于是问题转化为：每个任务有可开始时间 `start_i`、必须在 `end_i` 前完成、连续处理时长 `need_i`，判断单台机器能否排完所有任务。

`N<=10`，可以枚举任务集合而不必设计复杂调度贪心。

### 从任务顺序到状态压缩 DP

固定一个项目执行顺序后，每个项目都应尽可能早开始：若当前时间为 `t`，项目 `i` 最早从 `max(t,start_i)` 开始，最早结束于

\[
finish=\max(t,start_i)+need_i。
\]

更晚开始只会压缩后续任务空间，没有任何好处。因此定义 `dp[mask]` 为恰好完成集合 `mask` 后可以达到的最早结束时间。初始 `dp[0]=0`，其他为无穷大。对未在集合中的 `i`，若上述 `finish<=end_i`，就更新

`dp[mask | (1<<i)] = min(dp[...], finish)`。

完整集合状态可达即输出可行。

### 正确性说明

任意可行日程都有一个项目完成顺序，状态 DP 会枚举到该顺序。对同一个已完成集合，结束越早的日程不会比结束更晚的日程更差：后续每个项目的最早开始时间只会提前或不变。因此只保留最早结束时间不会丢失任何可行延伸。反过来，每次转移都把一段连续参加时间完整放在项目区间内，且接在已排日程之后，所以构造出的完整状态必然合法。

### 状态演算

两个项目分别为 `[0,3]` 和 `[1,4]`，持续时间都为 3，因此都需参加 2 小时。

- 先排项目 1：`dp[01]=2`；再排项目 2，从 `max(2,1)=2` 开始，到 4 结束，完整状态可达。
- 先排项目 2：它最早从 1 到 3，再排项目 1 会在 5 结束，超过截止时间 3，不可行。

DP 会保留第一种顺序并判断整体可行。

### 算法步骤

1. 对每个项目计算 `need_i=(end_i-start_i)/2+1`。
2. 建立大小 `2^N` 的数组，填无穷大，令 `dp[0]=0`。
3. 枚举所有 `mask`；不可达状态跳过。
4. 枚举所有不在 `mask` 中的项目 `i`。
5. 计算 `finish=max(dp[mask],start_i)+need_i`；若 `finish<=end_i`，更新新集合的最早结束时间。
6. 判断 `dp[(1<<N)-1]` 是否有限。

### 实现注意

- “严格超过一半”使偶数时长也要多于 `d/2`；例如时长 2 需要 2 小时，不能写成普通上取整。
- 项目之间允许空闲，`max(current,start_i)` 会自动等待。
- 题面时刻不超过 24，普通整数足够；无穷大取明显大于 24 的值。
- `N=1` 时同一转移逻辑即可处理。

### 复杂度

- 时间复杂度：`O(N*2^N)`，`N<=10` 时最多约一万次转移检查。
- 空间复杂度：`O(2^N)`。

## q02：小游戏

题目链接：[小游戏](https://www.nowcoder.com/questionTerminal/02f226d58f274064bba6132f752e5180)

### 题意转化与关键观察

一次合法跳跃选择两个不同位置 `a,b`，要求距离为正偶数且标记相同。距离为偶数等价于两个位置奇偶性相同，因此所有合法位置对恰好是在相同 `(标记, 位置奇偶性)` 分组内任选两个。

不能在每组枚举所有点对。扫描到当前位置时，把它和同组所有历史位置的贡献用四个统计量展开求和。

### 从单对得分到分组公式

设当前格为 `(i,Q_i)`，同组某个历史格为 `(p,Q_p)`，两者得分为

\[
(p+i)(Q_p+Q_i)=pQ_p+Q_i p+iQ_p+iQ_i。
\]

对组内所有历史格求和：

\[
add=sumPosQ+Q_i\cdot sumPos+i\cdot sumQ+i\cdot Q_i\cdot cnt。
\]

所以每个组只需维护：历史点数 `cnt`、位置和 `sumPos`、点数和 `sumQ`、位置乘点数和 `sumPosQ`。先用它们计算当前新增贡献，再把当前格加入四个统计量，可保证每对只算一次。

### 正确性说明

分组条件与合法条件完全等价，所以不会跨组误计。对当前格展开的四项之和逐项等于它与每个历史格的原得分；求和公式只是代数合并，没有改变贡献。每个无序合法位置对会在右端位置被扫描时计算一次，之前未计算、之后也不会重复，因此总和正确。

### 示例演算

同一分组已有位置 `p=1,Q_p=2`，当前为 `i=3,Q_i=4`。历史统计为 `cnt=1,sumPos=1,sumQ=2,sumPosQ=2`，公式得到

`2 + 4*1 + 3*2 + 3*4*1 = 24`，与直接计算 `(1+3)*(2+4)=24` 一致。

### 算法步骤

1. 为每个标记准备奇、偶两个统计组，每组含四个量。
2. 从 `i=1` 到 `N` 扫描，确定组键 `(L_i, i%2)`。
3. 用该组旧统计按公式计算 `add`，累加进答案。
4. 更新 `cnt+=1`、`sumPos+=i`、`sumQ+=Q_i`、`sumPosQ+=i*Q_i`。
5. 所有运算对 `10007` 取模，最后输出答案。

### 实现注意

- 位置编号必须从 1 开始；用 0 基下标直接代入会改变题目得分。
- 必须先计算贡献、后加入当前点，否则会把 `(i,i)` 这种距离为 0 的非法配对算进去。
- 标记范围为 `1..M`，可用数组；若实际实现按键存储，也可用哈希表。
- 乘法前用 64 位整数，并及时对 `10007` 取模，避免累计溢出。

### 复杂度

- 时间复杂度：`O(N)`，避免了最坏 `O(N^2)` 的点对枚举。
- 空间复杂度：`O(M)`，每个标记只有两套常数大小统计。

## q03：丢手绢

题目链接：[丢手绢](https://www.nowcoder.com/questionTerminal/83e03afc8b6745c893362febebb076bb)

### 题意转化与关键观察

每个人固定把所有手绢传给 `T_i`，可把人 `i` 看成节点并连一条有向边 `i->T_i`，得到每个节点出度恰为 1 的函数图。编号 `i` 的手绢在第 `r` 轮后位于 `f^r(i)`；它回到主人手中当且仅当 `f^r(i)=i`。

函数图中每个连通部分由一个有向环和若干指向环的树枝组成。只有环上节点能回到自己：长度为 `L` 的环中，手绢第一次回到原主正好在第 `L` 轮。故游戏结束轮数是所有环长度的最小值。

### 从遍历路径到环长

从任一未处理节点不断沿唯一出边前进，并记录本次路径中每个节点首次出现的步数 `depth`：

- 遇到未访问节点就继续；
- 若走到本次路径中已出现的节点 `u`，当前步数减 `depth[u]` 就是新环长度；
- 若走到以前已经彻底处理的节点，本路径不会产生新环。

可用三色状态 `0=未访问、1=当前路径、2=已完成`，一条路径结束后把路径节点全部标为 2。

### 正确性说明

出度为 1 保证沿边走的路径最终必然重复节点，重复段恰好是该分量唯一的环。深度差精确等于环上边数；进入环前的树枝只出现一次，不在重复段内，因此不会误算。遍历所有未处理起点会发现每个环一次，取最小环长正是第一个有人拿回自己手绢的轮数。

### 示例演算

若 `T=[2,3,1,5,4]`，函数图有环 `1->2->3->1`（长度 3）和 `4->5->4`（长度 2）。第 2 轮时后一个环上的人先拿回自己的手绢，所以答案为 `2`。

### 算法步骤

1. 初始化所有节点颜色为 0，答案为无穷大。
2. 对每个仍为 0 的起点建立空路径，沿 `T` 前进。
3. 每到新节点，标为 1，记录它在当前路径中的下标并压入路径。
4. 若遇到颜色 1 的节点，用“当前路径长度 - 该节点路径下标”更新答案。
5. 将本路径所有节点改为颜色 2。
6. 扫完所有节点后输出最小环长。

### 实现注意

- 若使用颜色 1，必须在结束一条路径后及时改成 2；这样再次遇到颜色 1 才能确定属于当前路径。
- 指向环的链长度不能加进环长。
- `T_i!=i` 保证没有自环，但通用写法仍可处理长度 1。
- `n<=200000`，使用迭代循环和数组，避免递归深度风险。

### 复杂度

- 时间复杂度：`O(n)`，每个节点至多进入路径并完成一次。
- 空间复杂度：`O(n)`，用于状态、路径位置和临时路径。

## q04：有趣的最大池化

题目链接：[有趣的最大池化](https://www.nowcoder.com/questionTerminal/2741361d86ca4d0c83c1ba9d8162527a)

### 题意转化与关键观察

要求输出每个长度为 `ks` 的滑动窗口最大值。相邻窗口只移出一个元素、加入一个元素；若每次重扫窗口会达到 `O(n*ks)`。应维护窗口中仍可能成为最大值的候选下标。

### 单调队列的维护规则

用双端队列保存下标，并让对应数组值从队首到队尾单调递减：

1. 新下标 `i` 到来前，若队首下标 `<i-ks+1`，它已离开当前窗口，弹出。
2. 从队尾弹出所有 `a[idx]<=a[i]` 的下标。新元素更大且更晚离开，这些旧元素以后不可能成为最大值。
3. 把 `i` 加到队尾。
4. 当 `i>=ks-1` 时，队首就是当前窗口最大值。

### 正确性说明

队列只删除两类无用元素：已经过期的元素不属于后续窗口；被更晚且不小于它的新元素支配的元素，在两者共同存在的所有未来窗口中都不可能胜过新元素。其余候选按值递减，因此队首值最大，又保证仍在窗口内，正是窗口最大值。每次窗口输出一次，不会遗漏。

### 示例演算

数组 `[16,19,15,13,16,20]`、`ks=3`：

- 读到 `19` 时弹掉队尾 `16`，队列首为 `19`；第一个窗口输出 `19`。
- 滑到 `[15,13,16]` 时，加入 `16` 会弹掉 `13,15`，输出 `16`。
- 最后加入 `20`，它支配队内所有较小值，输出 `20`。

结果为 `19,19,16,20`。

### 算法步骤

1. 初始化空双端队列，队列元素为数组下标。
2. 对 `i=0..n-1`：先删除队首所有过期下标。
3. 再删除队尾所有值不大于 `a[i]` 的下标，并将 `i` 入队。
4. 若窗口已经形成，输出 `a[deque.front]`。

### 实现注意

- 必须保存下标而不只是数值，否则无法判断元素何时过期。
- 相等值可删除旧下标、保留新下标，因为新下标生命周期更长。
- `ks=1` 时每个元素本身就是答案；`ks=n` 时只输出一个最大值。
- 严格遵守原题空格和换行格式，但不需要额外保存所有结果，可边计算边输出。

### 复杂度

- 时间复杂度：`O(n)`；每个下标最多入队一次、从一端出队一次。
- 空间复杂度：`O(ks)`，队列不会超过窗口大小。
