# 2024 秋招算法岗：算法思路

本文只整理算法推导与实现要点，不包含完整代码或输入输出模板。

## q01：小红的项链

题目链接：[小红的项链](https://www.nowcoder.com/questionTerminal/3da065cab096478eb603bbfca5af8b02)

### 题意转化与关键观察

把三个红珠位置排序为 `p1<p2<p3`，定义三个顺时针间距

`g1=p2-p1、g2=p3-p2、g3=n-p3+p1`，且 `g1+g2+g3=n`。

任意两颗相邻红珠之间的这段环形间距若小于 `k`，它们的最短距离必小于 `k`；反之，若三个间距都至少为 `k`，任意两红珠的两条环路中，较短者也不会小于 `k`。所以目标等价于把三个间距都调整到至少 `k`。

### 从交换操作到缺口公式

红珠和相邻白珠交换一格，会使它一侧的间距增加 1、另一侧的间距减少 1，相当于在三个间距之间搬运一个单位长度，代价为一次交换。

首先必须满足 `n=g1+g2+g3>=3k`，否则总长度不足，无论如何都无解。可行时定义每段缺口

\[
def_i=\max(0,k-g_i)。
\]

每次交换至多让某个不足间距增加 1，因此答案至少是 `D=sum(def_i)`。另一方面，总盈余不少于总缺口；三个间距在环上两两通过某颗红珠相邻，可以直接从任意有盈余的间距向任意有缺口的间距搬 1。持续搬运恰好 `D` 次即可补齐全部缺口，所以答案就是 `D`。

### 正确性说明

`n<3k` 的不可行性由间距总和直接推出。可行时，每个缺失单位都必须由至少一次红珠移动产生，给出 `D` 的下界；从盈余间距逐单位转移的构造始终不把供给间距降到 `k` 以下，并能补完所有缺口，使用恰好 `D` 次。上下界相等，公式最优。

### 示例演算

`n=12,k=3`，红珠位置为 `1,3,9`，三个间距为 `[2,6,4]`。第一段缺 1，第二段有盈余。把位置 3 的红珠顺时针移动一格，间距变成 `[3,5,4]`，只需 1 次，等于缺口和。若 `n=8,k=3`，因为 `8<9`，直接无解。

### 算法步骤

1. 将三个位置升序排列。
2. 计算三个环形间距 `g1,g2,g3`。
3. 若 `n<3*k`，输出 `-1`。
4. 否则计算 `ans=max(0,k-g1)+max(0,k-g2)+max(0,k-g3)`。
5. 输出 `ans`。

### 实现注意

- 第三段必须写成 `n-p3+p1`，不能漏掉首尾相接部分。
- 距离是环上边数；相邻编号位置的距离为 1，与间距定义一致。
- `n,k<=10^9`，`3*k` 可能溢出 32 位，所有位置、间距和答案使用 64 位整数。
- 已满足条件时三个缺口均为 0，答案自然为 0。

### 复杂度

- 每组只排序 3 个数并做常数次运算，时间 `O(1)`。
- 额外空间 `O(1)`，适合 `T<=10^4`。

## q02：小红玩纸牌

题目链接：[小红玩纸牌](https://www.nowcoder.com/questionTerminal/41bdac26deca40edbbffaf14203144e8)

### 题意转化与关键观察

一副得分牌型需要同一花色、五个连续牌值各一张。四种花色互不共享牌，可以完全独立求解；同一花色中若某个牌值缺失，它两侧也不可能组成同一副顺子，因此再按连续牌值段拆分。

在一个连续段内，设剩余数量为 `cnt[v]`。从最小可能起点向右处理长度 5 的窗口，并一次批量取出尽可能多的相同顺子。

### 左端贪心的推导

处理起点 `v` 时，之前起点的选择已确定。牌值 `v` 已不可能被任何更靠右的顺子使用：未来起点大于 `v`，其窗口不会包含 `v`。当前能取的最大套数为

\[
t=\min(cnt[v],cnt[v+1],...,cnt[v+4])。
\]

直接取 `t` 套并从五种牌中各扣 `t`。若少取 1 套，释放的牌只可能帮助起点 `v+1..v+4` 的未来顺子；这些未来窗口都共同包含牌值 `v+4`，而少取一套在 `v+4` 也只释放 1 张，因此最多换回 1 套，不会增加总数。故把当前窗口取满是安全的。

### 正确性说明

按起点归纳。假设更早起点已按贪心固定；通过上述交换论证，存在一个最优方案把当前起点数量提高到贪心值而不降低总套数。逐个起点执行后，存在一个最优方案与贪心在全部起点上一致，因此贪心结果最优。花色和缺口分段之间没有共享资源，把各段答案相加即为全局最优。

### 示例演算

某花色连续牌值 `1..5` 的数量为 `[2,1,2,1,2]`。窗口最小值为 1，所以批量取一套，剩余 `[1,0,1,0,1]`，无法再组成顺子，贡献 1。若牌值 `6` 也有牌，起点 2 的窗口仍因牌值 2 或 4 已为 0 而不能取，算法会自然处理重叠。

### 算法步骤

1. 按花色收集 `(牌值,数量)`，分别按牌值升序排序。
2. 遇到不连续牌值时结束当前段并从新段重新开始。
3. 对段内每个可能起点 `v`，取接下来 5 个剩余计数的最小值 `t`。
4. 令答案加 `t`，并把这 5 个计数各减 `t`。
5. 四种花色全部处理后输出总答案。

### 实现注意

- 输入每个“花色 + 牌值”只出现一次，无需合并重复记录。
- 牌值可达 `10^9`，不能按完整值域开数组；使用排序后的记录并按差是否为 1 分段。
- `cnt_i` 很大，必须批量扣减，不能一副一副模拟。
- 总套数可达 `10^13` 量级，计数和答案使用 64 位整数。

### 复杂度

- 排序时间 `O(n log n)`；每个起点只查看固定 5 个计数，扫描 `O(n)`。
- 空间复杂度 `O(n)`，用于按花色保存并排序记录。

## q03：小红的好数组

题目链接：[小红的好数组](https://www.nowcoder.com/questionTerminal/9a18a92ffe02479a99ef6f30070b1dc4)

### 题意转化与关键观察

最终数组需要选出一个“异常位置” `j`，其余 `n-1` 个元素全部等于某个多数值 `x`，而异常元素最终必须不等于 `x`。固定 `j,x` 后，其他元素的修改代价为绝对值和；异常元素若原值已不等于 `x` 可不动，若恰好等于 `x`，最少再改 1。

因此代价是

\[
cost(j,x)=\sum_{i\ne j}|a_i-x|+[a_j=x]。
\]

### 从绝对值和到中位数候选

固定异常位置后，剩余 `n-1` 个数到 `x` 的绝对值和在中位数处最小。把数组排序；删除位置 `j` 后，只需检查剩余序列的下中位数和上中位数。

若剩余数量为偶数，基础绝对值和在整个中位区间都相同：即使 `a_j` 碰巧等于一个端点，另一个端点可避免额外 1；若两个端点都等于 `a_j`，移出中位点至少使基础代价增加 1，不会优于直接支付异常项的 1。因此检查这两个候选足够。

用排序前缀和可在 `O(1)` 求任意候选值的全数组绝对偏差。设候选 `x=b[r]`，下标从 0 开始，且 `P[t]` 表示前 `t` 项之和，则

    left  = x*r - P[r]
    right = (P[n]-P[r+1]) - x*(n-r-1)
    allDist = left + right

相等元素放在 `r` 的哪一侧都只贡献 0，所以候选值有重复也不影响公式。最后从 `allDist` 减去被排除元素的 `|b[j]-x|`，再加碰撞指示项即可。

### 正确性说明

每个目标好数组至少可以指定一个异常位置；当 `n>=3` 时该位置唯一，而 `n=2` 时任选一端都不影响枚举覆盖性。对固定 `j`，绝对值和的凸性保证最优多数值位于中位区间；额外碰撞代价只有 0 或 1，上下中位候选按上述讨论总能达到不劣于区间外值的代价。因此对所有位置和两个候选取最小值就是全局最优。

### 示例演算

- `[2,2,5,2]`：选值 5 的位置为异常项、`x=2`，其他项无需修改且异常项已不同，答案为 0。
- `[3,3,3]`：无论排除哪个位置，剩余中位数都是 3，基础代价 0，但异常项也为 3，需把它改成 2 或 4，答案为 1。
- `n=2` 时 `[1,2]` 已满足目标，`[1,1]` 需改任意一个元素 1 次。

### 算法步骤

1. 将数组升序排序为 `b`，建立 64 位前缀和。
2. 枚举排序位置 `j` 作为异常元素。
3. 令剩余长度 `m=n-1`，计算其下、上中位数排名，并映射回跳过 `j` 后的原排序下标。
4. 对这两个候选值 `x`，用前缀和求全数组 `sum|b_i-x|`，再减 `|b_j-x|`。
5. 若 `b_j==x`，候选代价再加 1；更新全局最小值。
6. 输出最小值。

### 实现注意

- 剩余序列排名映射：若排名小于 `j`，原下标不变，否则加 1。
- 绝对偏差和最高约 `10^14`，必须用 64 位整数。
- 多数值取中位数，不是平均数；剩余数量为偶数时要检查上下两个端点。
- 异常元素允许修改到任意与 `x` 不同的整数，所以碰撞时额外 1 总能做到。

### 复杂度

- 排序 `O(n log n)`；前缀和后每个异常位置只检查两个候选，扫描 `O(n)`。
- 空间复杂度 `O(n)`；适合 `n<=10^5`。

## q04：小红的子串权值和

题目链接：[小红的子串权值和](https://www.nowcoder.com/questionTerminal/f22b0c6c03b34af995b1cae4547b4fde)

### 题意转化与关键观察

任意非空子串的连续段数等于 `1 + 子串内部相邻字符不同的边界数`。因此无需枚举子串，可以把总权值拆为：每个子串的基础贡献 1，加上原串每个异字符边界对所有覆盖它的子串贡献 1。

### 从边界贡献到闭式公式

长度 `n` 的字符串共有 `n(n+1)/2` 个非空子串，先贡献相同的基础值。

对 1 基边界 `i`（位于字符 `i` 与 `i+1` 之间），若 `s[i]!=s[i+1]`，一个子串覆盖该边界需要左端点选在 `1..i`、右端点选在 `i+1..n`，选择数为

\[
i\times(n-i)。
\]

所以

\[
ans=\frac{n(n+1)}2+\sum_{i:s_i\ne s_{i+1}}i(n-i)。
\]

### 正确性说明

对任一子串，基础项恰好计入它的第一个连续段；它内部每经过一个异字符边界，连续段数恰好增加 1。贡献法对每个边界统计所有且仅有覆盖它的子串，因此每个子串最终被累计的次数正好等于其连续段数。交换求和顺序不会重复或遗漏，公式正确。

### 示例演算

`s=010,n=3`。基础子串数为 `6`；边界 1 不同，贡献 `1*(3-1)=2`；边界 2 也不同，贡献 `2*(3-2)=2`。总答案 `6+2+2=10`。逐个子串的权值为 `1,1,1,2,2,3`，和也为 10。

### 算法步骤

1. 用 64 位整数初始化 `ans=n*(n+1)/2`。
2. 枚举 0 基位置 `i=0..n-2`。
3. 若 `s[i]!=s[i+1]`，边界左侧可选数为 `i+1`，右侧可选数为 `n-i-1`。
4. 令 `ans+=(i+1)*(n-i-1)`。
5. 输出 `ans`。

### 实现注意

- 公式中的边界编号若用 0 基，应写成 `(i+1)*(n-i-1)`，避免下标偏一。
- 全相同字符串没有额外边界贡献，但每个子串仍有权值 1。
- 答案为立方量级；`n<=200000` 时必须用 64 位整数，并在乘法前提升类型。
- 只需一次扫描，不必显式分段或枚举子串。

### 复杂度

- 时间复杂度 `O(n)`。
- 额外空间复杂度 `O(1)`。
