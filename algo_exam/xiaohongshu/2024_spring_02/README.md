# 2024 春招算法岗第二批：算法思路

本文按“观察—推导—正确性—例子—实现”的顺序整理本批算法题，不包含完整代码或输入输出模板。

## q01｜[小苯的文章浏览](https://www.nowcoder.com/questionTerminal/31e5e8a1da8a4a5b84f468a53933ff25)

### 题意转化与关键观察

同一个用户可能出现多次，但只需输出他第一次浏览的时刻顺序。也就是说，要对输入序列做“稳定去重”：保留每个 ID 的第一次出现，删除后续重复项，并且不能改变保留项之间的先后顺序。

### 状态设计

维护哈希集合 `seen`，表示此前已经出现过的用户 ID。顺序读到 `id` 时：

- 若 `id∉seen`，当前记录就是该用户的第一次浏览，应立即输出或加入答案，并插入 `seen`；
- 若 `id∈seen`，此前已经记录过第一次浏览，忽略当前记录。

集合只负责判断“是否见过”，顺序由输入扫描本身保证；使用会自动排序的树集合来直接输出，会破坏题目要求的时间顺序。

### 正确性说明

对第 `i` 条记录归纳：处理前，`seen` 恰好包含前 `i-1` 条记录出现过的所有 ID。若当前 ID 不在集合，它在更早位置从未出现，所以第 `i` 条确是第一次；若已在集合，它至少出现过一次，当前不应输出。每个用户恰好在首次出现时输出一次，且扫描方向保持所有首次出现的原顺序。

### 示例演算

输入浏览序列为：

`alice, bob, alice, carol, bob`。

集合变化为：

1. `alice` 未见，输出并加入；
2. `bob` 未见，输出并加入；
3. `alice` 已见，忽略；
4. `carol` 未见，输出并加入；
5. `bob` 已见，忽略。

最终顺序是 `alice, bob, carol`。

### 算法步骤

1. 创建空哈希集合 `seen`。
2. 从第 1 条到第 `n` 条顺序读取 ID。
3. 查询 `seen`；若不存在：
   - 输出或追加该 ID；
   - 将其插入 `seen`。
4. 若已存在则继续下一条。

### 边界与实现注意

- `n=1` 时唯一 ID 必然输出。
- ID 是长度不超过 20 的字符串，应按完整字符串、区分大小写地比较。
- 若边读边输出，可省去答案数组；若平台要求集中输出，可保存首次出现列表。
- 不要先排序再去重，也不要遍历哈希集合输出，因为二者都不能保留首次出现顺序。
- 哈希碰撞由语言标准容器处理，不应只保存自定义短哈希值而丢失原串校验。

### 复杂度

哈希集合查询和插入的期望时间为 `O(1)`，总期望时间 `O(n)`；设不同用户数为 `u`，集合空间 `O(u)`，若另存答案也是 `O(u)`。`n≤10^5` 时足够。

## q02｜[小苯的粉丝关注](https://www.nowcoder.com/questionTerminal/697cf95e85cc4061b1d3429d39e00780)

### 题意转化与关键观察

对旧账号 `i` 有三种互斥选择：

1. 不使用，涨粉 0、代价 0；
2. 普通推荐，涨粉 `floor(a_i/2)`、使用 1 个旧账号；
3. 把它作为全局至多一个“多次推荐账号”，涨粉 `a_i`、仍只计使用 1 个旧账号。

目标是涨粉数恰好为 `x`，并最小化使用过的旧账号数。特别注意：多次推荐描述的是同一个账号的强化效果，样例的最小量按使用的旧账号计，这个账号不会因为多发文章而重复计入答案。

### 动态规划状态与转移

定义 `dp[sum][used]`：处理完若干旧账号后，恰好得到 `sum` 个粉丝、是否已经使用过特殊账号 `used∈{0,1}` 时，最少使用多少个旧账号。

初始只有 `dp[0][0]=0`，其他状态为无穷大。处理账号 `i` 时，从旧表向新表做三类转移：

- 不用：`next[sum][used]←dp[sum][used]`；
- 普通：若 `sum+floor(a_i/2)≤x`，

  `next[sum+floor(a_i/2)][used]←min(...,dp[sum][used]+1)`；

- 特殊：仅从 `used=0` 出发，若 `sum+a_i≤x`，

  `next[sum+a_i][1]←min(...,dp[sum][0]+1)`。

答案为 `min(dp[x][0],dp[x][1])`。

### 正确性说明

每个账号在最终方案中恰好属于“不用、普通、特殊”三类之一，且特殊类最多一个。按账号顺序处理时，`used` 完整记录了特殊名额是否已消耗，`sum` 记录了对后续有影响的全部涨粉信息。任意合法方案都能按其对当前账号的选择进入对应转移；反过来，每条转移都不会重复使用账号或超过一个特殊账号。以最小值合并相同状态，故最终得到最少账号数。

### 状态演算示例

`n=2,x=6,a=[6,4]`。处理第一个账号时：

- 不用仍是 `dp[0][0]=0`；
- 普通可到 `dp[3][0]=1`；
- 特殊可到 `dp[6][1]=1`。

目标 6 已由一个特殊账号精确达到，所以答案为 1。若目标改为 5，两个账号普通贡献 `3+2=5`，答案为 2。

### 算法步骤

1. 建立 `(x+1)×2` 的 DP 数组，填入无穷大，设置 `dp[0][0]=0`。
2. 依次处理每个 `a_i`，新建 `next` 并先复制“不选”状态。
3. 从旧 `dp` 枚举 `sum` 和 `used`，分别尝试普通转移。
4. 仅从 `used=0` 尝试完整贡献的特殊转移。
5. 用 `next` 替换 `dp`。
6. 取目标两状态的最小值；仍为无穷大则输出 `-1`。

### 边界与实现注意

- 必须要求“恰好 `x`”；贡献超过 `x` 后无法减少，直接丢弃，不能把它压成 `x`。
- `floor(a_i/2)` 可能为 0；花一个账号却不涨粉不会改善最优值，但通用转移仍不会破坏正确性。
- 用新旧两层数组最稳妥；若原地更新，必须倒序并谨慎安排 `used`，否则可能在同一轮重复使用账号。
- 无穷大可取大于 `n` 的值，做 `+1` 前先判断状态可达。
- `n,x≤100`，无需进一步优化。

### 复杂度

每个账号扫描 `x+1` 个和两个特殊状态，时间复杂度 `O(nx)`；滚动数组空间 `O(x)`。最大仅约一万次状态更新，远低于限制。

## q03｜[小红的点赞(二)](https://www.nowcoder.com/questionTerminal/b5bd2d0d30154ae6bbd11b25b56dbd6d)

### 题意转化与关键观察

固定目标笔记 `i`。若它当前已经达到全局最大点赞数，则无需等待，答案就是初始总和。否则设最终把它加到 `y`，需要给它点赞：

`d=y-a_i>0`

次。由于同一笔记不能连续增加，`d` 次目标点赞之间至少要插入 `d-1` 次对其他笔记的点赞；按“目标、其他、目标、其他、…、目标”排列时，这个下界可以达到。

### 容量不等式与公式推导

最终目标笔记必须并列最多，所以其他笔记 `j` 最多只能增加到 `y`，可承担的分隔点赞容量为 `y-a_j`。全部其他笔记总容量：

`C(y)=Σ_{j≠i}(y-a_j)=(n-1)y-(S-a_i)`，

其中 `S=Σa_j`。为了放下至少 `d-1=y-a_i-1` 次分隔点赞，需要：

`(n-1)y-(S-a_i)≥y-a_i-1`，

化简为：

`(n-2)y≥S-2a_i-1`。

同时必须有 `y≥M=max a_j`。当 `n≥3` 且 `a_i<M` 时，最小可行终值为：

`y=max(M,ceil((S-2a_i-1)/(n-2)))`。

最少新增点赞数是 `d+(d-1)=2d-1`，所以答案：

`S+2(y-a_i)-1`。

### 正确性说明

必要性来自：目标的相邻两次点赞之间必须有其他笔记分隔，且任何其他笔记不能超过 `y`。若总容量至少 `d-1`，就从各笔记容量中任意取满 `d-1` 个分隔点赞，再与目标点赞交替排列；每次其他点赞都被目标点赞隔开，所以不要求不同分隔项彼此再交替。最终所有其他笔记不超过 `y`，目标恰为 `y`，构造成立。

### 示例演算

`a=[1,4,2]`，`S=7,M=4`。考虑第 1 篇：

`y=max(4,ceil((7-2-1)/(3-2)))=4`，

`d=3`，最少新增 `2·3-1=5` 个赞。可按“第1篇、第3篇、第1篇、第3篇、第1篇”增加，最终为 `[4,4,4]`，总和 12。

考虑第 3 篇时，`y=4,d=2`，只需 3 次，总和为 10。

### `n=1` 与 `n=2` 的单独推导

- `n=1`：唯一笔记当前天然最多，答案是 `S`。
- `n=2`：若目标已不小于另一篇，答案为 `S`；若只落后 1，给目标点赞一次即可，答案 `S+1`；若落后至少 2，则每增加目标两次之间都必须给另一篇至少加一次，二者差距最多只缩小 1，永远无法追平，输出 `-1`。

### 算法步骤

1. 预处理 64 位总和 `S` 和最大值 `M`。
2. 依次处理每个目标 `i`：
   - 若 `a_i=M`，输出 `S`；
   - 若 `n=1`，同样输出 `S`；
   - 若 `n=2`，按差值 1 或更大分类；
   - 否则计算上取整下界，与 `M` 取最大得到 `y`；
   - 输出 `S+2(y-a_i)-1`。
3. 正数上取整可用 `(num+den-1)/den`。

### 边界与实现注意

- “最多”允许并列，不要求目标严格大于其他笔记。
- 目标已经最大时允许 0 次新增，不能套用 `2d-1` 得到负数。
- `S` 可达 `10^14`，公式所有量都使用 64 位整数。
- 在本题正整数约束且 `a_i<M,n≥3` 时，上取整分子为正；若写通用整除函数，仍应正确处理符号。
- 输出有 `n` 行，注意使用缓冲输出。

### 复杂度

预处理 `O(n)`，每篇笔记只做常数次算术，整体时间复杂度 `O(n)`；除输入和输出外额外空间 `O(1)`。`n≤10^5` 时无需二分或逐笔记模拟。
