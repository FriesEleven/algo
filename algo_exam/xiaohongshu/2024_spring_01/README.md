# 2024 春招算法岗第一批：算法思路

本文按“观察—推导—正确性—例子—实现”的顺序整理本批算法题，不包含完整代码或输入输出模板。

## q01｜[小红的碾压墙](https://www.nowcoder.com/questionTerminal/ec8b42da899046589e40a0950b4cf7f8)

### 题意转化与关键观察

两张致命射击按顺序结算：第一张从 `n` 个随从中等概率选一个，第二张再从剩余 `n-1` 个中等概率选一个。两次不会命中同一个随从，因此可以把结果看成从 `n` 个位置中“不放回地抽取两个位置”，且抽取顺序不同算不同过程。

### 概率推导

所有有序结果数为：

`n(n-1)`。

要恰好等价于碾压墙，最终被消灭的位置集合必须是“最左”和“最右”。有利的有序结果只有两种：

1. 第一张消灭最左，第二张消灭最右；
2. 第一张消灭最右，第二张消灭最左。

每种过程的概率都是 `1/n·1/(n-1)`，所以总概率为：

`P=2/[n(n-1)]`。

### 正确性说明

碾压墙只消灭初始队列两端的两个随从。第一枪打掉中间随从后，即便队列视觉上出现新的“端点”，最终消灭集合也已经不等于原来的最左和最右；题目比较的是两张牌造成的消灭效果，而不是第二枪当时的两端。因此有利结果恰好只有上述两个顺序。

### 示例演算

`n=4` 时共有 `4·3=12` 个有序结果。把位置记为 `1,2,3,4`，有利结果为 `(1,4)` 和 `(4,1)`，概率为 `2/12=1/6≈0.1666666667`。

`n=2` 时样本空间只有 `(1,2)`、`(2,1)`，两种都成功，所以概率为 1。

### 算法步骤

1. 把 `n` 转成浮点数或先用 64 位整数计算分母。
2. 计算 `ans=2.0/(n·(n-1))`。
3. 使用固定小数格式输出 10 位小数。

### 边界与实现注意

- `n≥2`，分母不会为 0。
- 若 `n(n-1)` 先用普通 32 位整数计算，`n=10^6` 时会溢出；应先转 64 位或浮点。
- 分子必须写成浮点值，避免整数除法先得到 0。
- 输出要求是保留 10 位小数，不是输出分数，也不需要取模。
- `float64` 对约 `10^{-12}` 量级的结果仍有足够精度完成 10 位小数格式化。

### 复杂度

只进行常数次算术运算，时间复杂度 `O(1)`、额外空间 `O(1)`，与 `n` 大小无关。

## q02｜[小红书推荐算法](https://www.nowcoder.com/questionTerminal/2408a65ee1c1433284fdbe1ab8c79245)

### 题意转化与关键观察

每件商品的排名只由两个量决定：它命中了多少个用户搜索词，以及它在输入中的原始顺序。搜索词需要被大量查询，适合存入哈希集合；命中数相同的商品必须保持默认顺序，等价于稳定地按得分降序排序。

### 得分与排序键推导

设搜索词集合为 `Q`，商品 `i` 的属性集合为 `A_i`，那么：

`score_i=|Q∩A_i|`。

题目保证搜索词互不相同、同一商品的属性也互不相同，因此逐属性检查是否属于 `Q` 并累加即可，不会对同一关键词重复计分。

给每件商品保存三项：`name、score、index`。完整排序键是：

1. `score` 降序；
2. `index` 升序。

也可以只按得分使用稳定排序，但显式加入原序号通常更不易受排序库稳定性影响。

### 正确性说明

若商品 A 得分高于 B，规则明确要求 A 在前；若得分相同，输入序号较小者优先。比较器恰好逐层实现这两个规则，所以任意一对商品的相对顺序都符合题意。排序完成后，整个序列自然是唯一的合法推荐顺序。

### 示例演算

搜索词为 `{art,travel}`：

- 商品 A 属性 `{art,food}`，得分 1；
- 商品 B 属性 `{travel,art}`，得分 2；
- 商品 C 属性 `{tech}`，得分 0。

输出顺序为 B、A、C。若再有商品 D 也得 1 分且输入在 A 之后，则 A 仍排在 D 前。

### 算法步骤

1. 读入 `q` 个搜索词并插入哈希集合 `Q`。
2. 对第 `i` 个商品：
   - 初始化 `score=0`；
   - 扫描其全部属性，若属性存在于 `Q` 就加 1；
   - 保存商品名、得分和输入序号 `i`。
3. 按“得分降序、序号升序”排序商品记录。
4. 依次输出排序后的名称。

### 边界与实现注意

- 得分为 0 的商品也必须输出，并按输入顺序排在同分组中。
- 字符串按完整内容哈希比较，不能只比较前缀。
- 若选择稳定排序，要确认所用 API 确实稳定；否则显式比较 `index`。
- 所有商品名互不相同，但排序正确性不依赖这一条件。
- 总属性数只有 `3·10^4`，无需为每件商品单独构造属性集合。

### 复杂度

设所有商品属性总数为 `M`。哈希查询期望时间 `O(M)`，排序 `O(n log n)`，总时间 `O(M+n log n)`；搜索集合和商品记录占 `O(q+n)` 空间。`n,q,M≤3·10^4` 量级，可直接完成。

## q03｜[小红的点赞](https://www.nowcoder.com/questionTerminal/14a793274f5a489982bce57043e65292)

### 题意转化与关键观察

每次点赞只会改变一篇笔记点赞数的奇偶性。具体数值有多大并不影响“何时全部为偶数”，状态只需记录当前有多少篇笔记为奇数。设该数量为 `k`：

- 选中奇数笔记的概率为 `k/n`，它变偶数，状态到 `k-1`；
- 选中偶数笔记的概率为 `(n-k)/n`，它变奇数，状态到 `k+1`。

最终总赞数等于初始总赞数加上到达状态 0 所需的点赞次数，因此只需求吸收时间的期望。

### 期望方程与差分推导

令 `E_k` 为从 `k` 个奇数状态首次到达 0 的期望步数。边界为：

`E_0=0`，`E_n=1+E_{n-1}`。

对 `1≤k<n` 做一步分析：

`E_k=1+(k/n)E_{k-1}+((n-k)/n)E_{k+1}`。

直接解三对角方程不方便，定义相邻差分 `D_k=E_k-E_{k-1}`。整理上式：

`kD_k=n+(n-k)D_{k+1}`，

即：

`D_k=[(n-k)D_{k+1}+n]/k`。

由 `E_n=1+E_{n-1}` 得 `D_n=1`，于是可从 `n-1` 倒推到 1。最后：

`E_k=D_1+D_2+...+D_k`。

### 正确性说明

每篇笔记被选概率相同，所以给定奇数笔记数量 `k` 后，下一步落到 `k-1` 或 `k+1` 的概率只由 `k` 决定，与哪些具体笔记为奇数无关，状态压缩保持了完整的马尔可夫信息。期望方程来自对第一步分类，差分只是等价代数变形，因此倒推得到唯一的有限期望解。

### 状态演算示例

`n=2` 时 `D_2=1`，再算：

`D_1=[(2-1)·1+2]/1=3`。

所以 `E_1=3`、`E_2=D_1+D_2=4`。若初始点赞为 `[1,0]`，当前有一篇奇数笔记，期望再获得 3 个赞；最终总赞数期望是初始和 1 加 3，即 4。

### 算法步骤

1. 扫描初始数组，计算 `sumA mod MOD` 和奇数个数 `k0`。
2. 若 `k0=0`，直接输出 `sumA`。
3. 预处理 `1..n` 在模 `MOD=10^9+7` 下的乘法逆元。
4. 建立 `D`，令 `D[n]=1`。
5. 对 `k=n-1..1`：

   `D[k]=((n-k)·D[k+1]+n)·inv[k] mod MOD`。

6. 累加 `D[1..k0]` 得到 `E_{k0}`，输出 `sumA+E_{k0}` 取模。

### 边界与实现注意

- 初始已经全偶数时，“第一次出现”就是当前时刻，附加步数为 0。
- 所有除法都必须转为模逆元乘法；`n≤10^5<MOD`，`1..n` 均可逆。
- 可用线性公式预处理逆元，也可逐个快速幂，但后者会多一个对数因子。
- 初始总和可达 `10^14`，累加时使用 64 位并及时取模。
- 乘法 `(n-k)·D[k+1]` 也使用 64 位中间量。

### 复杂度

扫描、逆元预处理和差分倒推都是线性，时间复杂度 `O(n)`；`D` 与逆元数组占 `O(n)` 空间。若复用线性逆元并在倒推时按需累计，可进一步压缩部分存储，但 `n=10^5` 时没有必要。
