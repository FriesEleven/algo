# 2023 秋招研发岗第一批：算法思路

本文按“观察—推导—正确性—例子—实现”的顺序整理本批算法题，不包含完整代码或输入输出模板。

## q01｜[游游的排列统计](https://www.nowcoder.com/questionTerminal/4c58fc41f25d4598913ceda30e66bf01)

### 题意转化与关键观察

要把 `1..n` 各放一次，并保证每一对相邻数字之和都不是素数。`n≤10`，直接枚举 `n!` 个排列虽然勉强不大，但更自然的做法是记录“已经用了哪些数字”和“当前最后一个数字”。后续能否接入新数字，只与这两个信息有关，与更早的排列顺序无关。

### 状态与转移的逐步推导

1. 用 `n` 位二进制数 `mask` 表示已使用的数字集合，第 `x-1` 位为 1 表示数字 `x` 已出现。
2. 定义 `dp[mask][last]`：使用集合 `mask` 中的全部数字组成合法排列，且最后一个数字为 `last` 的方案数。
3. 单个数字没有相邻约束，所以对每个 `x∈[1,n]`，初始化 `dp[1<<(x-1)][x]=1`。
4. 从状态 `(mask,last)` 枚举尚未使用的 `next`。只有 `last+next` 不是素数时，才可追加：

   `dp[mask∪{next}][next] += dp[mask][last]`。

5. 满集合 `full=(1<<n)-1` 已经放完所有数字，答案是 `Σ_last dp[full][last]`。

只需预先判断 `2..2n` 是否为素数；注意 `1` 不是素数。

### 正确性说明

对任意一个被计入 `dp[mask][last]` 的排列，删除末尾 `last` 后，会唯一得到一个规模更小的合法状态；反过来，从较小状态追加一个满足“相邻和非素数”的 `next`，不会改变已有相邻对，只新增最后这一对，因此仍合法。每个排列的最后一步唯一，转移既不漏计也不重计。

### 示例演算

取 `n=3`。`1+2=3`、`2+3=5` 都是素数，只有 `1+3=4` 可相邻。因此会产生状态 `dp[{1,3}][3]=1` 和反向状态，但数字 2 无法接到它们后面，最终满集合的所有状态均为 0，答案为 0。

### 算法步骤

1. 筛出 `2..2n` 的素数。
2. 建立大小为 `2^n×n` 的计数表并初始化所有单元素状态。
3. 依次枚举 `mask`、`last`；跳过计数为 0 的状态。
4. 枚举每个未使用的 `next`，检查 `isPrime[last+next]`，合法时累加到新状态。
5. 汇总满集合的全部结尾。

### 边界与实现注意

- 数字值是 `1..n`，位编号通常是 `0..n-1`，转换时避免偏移错误。
- `n=2` 时也按同一转移处理；若唯一相邻和为素数，答案就是 0。
- 计数上界不超过 `n!`，但统一使用 64 位整数更安全。
- 本题不取模，不能擅自对答案取模。

### 复杂度

共有 `2^n·n` 个状态，每个状态最多尝试 `n` 个新数字，时间复杂度 `O(n^2·2^n)`，空间复杂度 `O(n·2^n)`。`n≤10` 时状态量约一万，远低于限制。

## q02｜[游游的you矩阵](https://www.nowcoder.com/questionTerminal/e1bf88d96a494c40a3fcef0b0e16bbcb)

### 题意转化与关键观察

两条直角边必须一横一竖，所以直角顶点必定是三个字符中的一个；另两个顶点分别与它同行、同列。一个轴对齐直角三角形的直角顶点是唯一的，因此可以“枚举直角顶点并计算贡献”，无需枚举三个格子。

### 公式推导

把 `y、o、u` 映射成三个类别。预处理：

- `row[i][c]`：第 `i` 行字符 `c` 的数量；
- `col[j][c]`：第 `j` 列字符 `c` 的数量。

若格子 `(i,j)` 的字符为 `c`，另外两种字符为 `x,z`，合法三角形有两种分工：

1. 同行端点选 `x`，同列端点选 `z`，有 `row[i][x]·col[j][z]` 种；
2. 同行端点选 `z`，同列端点选 `x`，有 `row[i][z]·col[j][x]` 种。

所以该格贡献为两项之和。三个字符互不相同，当前格不会被计入 `x` 或 `z` 的频次，不必减 1。

### 正确性说明

任意合法三角形都有且仅有一个直角顶点。固定该顶点后，另外两个顶点一个同行、一个同列，而且字符分配只可能是上述两种之一，所以它一定被公式计数一次。反过来，公式选择的两个格子分别同行、同列且字符与直角顶点恰好构成 `y/o/u`，必然形成题目要求的三角形。

### 示例演算

矩阵为：

`y o`
`u y`

以左上角 `y` 为直角顶点，同行有一个 `o`、同列有一个 `u`，贡献 1；以右下角 `y` 为直角顶点，也能选择同行 `u` 和同列 `o`，再贡献 1，总数为 2。

### 算法步骤

1. 读入矩阵，同时统计每行和每列三种字符的频次。
2. 再遍历每个格子；非 `y/o/u` 字符直接跳过。
3. 找出当前字符之外的两个类别 `x,z`。
4. 按两项乘积公式计算当前贡献并累加。
5. 输出总贡献。

### 边界与实现注意

- `n=1` 或 `m=1` 时不可能同时拥有水平、垂直两条非零直角边，公式自然得到 0。
- 行、列下标及字符类别的映射要统一。
- 单个乘积最多约为 `10^6`，全矩阵累加可达 `10^12`，答案必须使用 64 位整数。
- 若输入可能含其他字符，它们可以保存在矩阵中，但不参与三类计数。

### 复杂度

统计和求和各扫描一次矩阵，时间复杂度 `O(nm)`。行列计数额外占 `O(n+m)`；为第二遍扫描保存矩阵时，总空间为 `O(nm)`。`n,m≤1000` 时可满足内存限制。

## q03｜[游游的元素修改](https://www.nowcoder.com/questionTerminal/2e3557c96138444db7eca60e8afaaac7)

### 题意转化与关键观察

一次操作把某个元素减 1、另一个元素加 1，本质是在数组内部转移一个单位，总和始终不变。目标数组每项都在 `[l,r]`，所以其总和必须位于 `[nl,nr]`；这也是可行的充要条件。

### 从缺口到最少操作数

定义：

- `need=Σ max(0,l-a_i)`：所有过小元素至少还要接收多少单位；
- `extra=Σ max(0,a_i-r)`：所有过大元素至少要送出多少单位。

一次转移最多让 `need` 减 1，也最多让 `extra` 减 1，因此任何方案至少要做 `max(need,extra)` 次。

这个下界可以达到：

1. 先让过大元素向过小元素转移，配对消去 `min(need,extra)`。
2. 若 `need>extra`，总和不小于 `nl` 保证其他元素在不降到 `l` 以下的前提下还有足够单位可供转移。
3. 若 `extra>need`，总和不大于 `nr` 保证其他元素在不升到 `r` 以上的前提下还有足够容量接收。

所以答案恰为 `max(need,extra)`。

### 正确性说明

若 `sum<nl`，任何区间内数组的总和都至少是 `nl`，而操作又不改总和，必然无解；`sum>nr` 同理。反之，当总和落在区间内，上述“先配对、再利用区间内余量或容量”的构造总能把所有元素调整进区间。

### 示例演算

`l=3,r=5,a=[1,4,7]`。总和 12 位于 `[9,15]`；`need=2`、`extra=2`。连续把末尾元素的两个单位转给首元素，得到 `[3,4,5]`，正好 2 次。

若 `a=[1,5,5]`，则 `need=2,extra=0`。可以从两个值为 5 的元素各转 1 给首元素，2 次后得到 `[3,4,4]`，说明没有“超上界溢出”时仍可能需要操作。

### 算法步骤

1. 对每组数据线性扫描，累计 `sum、need、extra`。
2. 若 `sum<nl` 或 `sum>nr`，输出 `-1`。
3. 否则输出 `max(need,extra)`。

### 边界与实现注意

- `n、l、r、a_i` 的乘积和总和都可能超过 32 位，`sum、nl、nr、need、extra` 全部使用 64 位整数。
- `l=r` 时目标值唯一；只要总和等于 `nl`，公式仍成立。
- 多组数据的 `n` 总和不超过 `2·10^5`，无需跨测试保存数组。
- 每次操作必须选择两个不同元素；题目保证 `n≥2`，构造不会受此限制。

### 复杂度

每组只扫描一次数组，时间复杂度 `O(n)`、额外空间 `O(1)`。所有测试的总时间为 `O(Σn)`，符合 1 秒级约束。

## q04｜[游游的好串](https://www.nowcoder.com/questionTerminal/7aad9d56acca40d9a7eb64cf6ca3cc0c)

### 题意转化与关键观察

把字符 `0` 记为 `+1`、`1` 记为 `-1`，定义前缀和 `pre[0]=0`。子串 `s[l..r]` 的一个前缀 `s[l..t]` 中，0 严格多于 1，当且仅当：

`pre[t]-pre[l-1]>0`，即 `pre[t]>pre[l-1]`。

因此固定左端点前一个位置 `i=l-1` 后，需要找从 `i+1` 开始第一次出现 `pre[j]≤pre[i]` 的位置。

### 贡献公式与数据结构推导

令 `nextLE[i]` 为右侧第一个满足 `pre[j]≤pre[i]` 的下标：

- 在 `j` 之前，所有前缀和都严格大于 `pre[i]`，所以终点 `i+1..j-1` 全部合法；
- 到 `j` 时严格条件首次失败，更后的终点也包含这个失败前缀，均不合法。

故位置 `i` 的贡献是 `nextLE[i]-i-1`；若不存在阻断位置，就把 `nextLE[i]` 视为 `n+1`，贡献 `n-i`。

从右向左扫描前缀下标，用栈维护候选位置。处理 `i` 时，弹出所有 `pre[stackTop]>pre[i]` 的位置，因为它们不能成为“小于等于”的阻断点；弹完后的栈顶就是最近的 `nextLE[i]`，随后压入 `i`。

### 正确性说明

扫描方向保证栈中下标都在 `i` 右侧。被弹出的候选值严格大于 `pre[i]`，对当前位置无效；又因为当前下标 `i` 比它更靠左且前缀值更小或相等，它对未来更左的位置不会比 `i` 更优，因此可永久删除。剩余栈顶既满足值不大于当前值，又是未被支配候选中下标最近的一个。

### 状态演算示例

`s=001`，映射后前缀和为 `[0,1,2,1]`。

- `i=0` 右侧没有前缀和小于等于 0，贡献 3，对应 `0、00、001`；
- `i=1` 的第一个阻断点是 `j=3`（`pre[3]=pre[1]=1`），贡献 1，对应第二个字符 `0`；
- `i=2` 立刻在 `j=3` 被阻断，贡献 0。

总答案为 4。

### 算法步骤

1. 构造长度 `n+1` 的前缀和数组。
2. 初始化空栈和 64 位答案，从 `i=n` 逆序扫到 `0`。
3. 当栈顶前缀和严格大于 `pre[i]` 时持续弹栈。
4. 若栈非空，累加 `stackTop-i-1`；否则累加 `n-i`。
5. 把 `i` 压栈。只有 `i=0..n-1` 的贡献对应非空子串；`i=n` 的贡献为 0，保留它可作为候选阻断点。

### 边界与实现注意

- 条件是“严格大于”，所以阻断条件必须是 `≤`；弹栈条件必须写成严格 `>`。
- 以 `1` 开头的子串第一步就失败，公式会给出 0。
- 答案最多为 `n(n+1)/2`；`n=10^5` 时超过 32 位，必须使用 64 位整数。
- 若不希望处理虚拟 `n+1`，可以直接在空栈分支累加 `n-i`。

### 复杂度

每个前缀下标至多入栈、出栈各一次，时间复杂度 `O(n)`，前缀和与栈空间均为 `O(n)`，适合 `|s|≤10^5`。
