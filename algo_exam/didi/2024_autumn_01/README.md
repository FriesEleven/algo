## q01：对比之美

题目链接：[对比之美](https://www.nowcoder.com/questionTerminal/0fcbb83370124426bfee75aca43b7ee7)

### 题意转化与关键观察

需要选择非负整数 `a_1..a_n`，满足总和为 `m`，最大化相邻差之和

\[
F=\sum_{i=2}^{n}|a_i-a_{i-1}|。
\]

直接枚举摆法没有意义，因为 `n,m` 都可到 `10^9`。关键是先给 `F` 找一个与具体摆法无关的上界，再判断这个上界能否构造达到。

### 从定义到公式的推导

对每条相邻边使用 `|x-y|<=x+y`：

\[
F\le \sum_{i=2}^{n}(a_i+a_{i-1})
=a_1+a_n+2\sum_{i=2}^{n-1}a_i。
\]

每个内部格子的收藏品在左右两条边中各出现一次，首尾格子只出现一次，所以右式不超过 `2*sum(a_i)=2m`。

还要按格子数讨论这个上界能否取到：

- `n=1`：没有相邻边，答案只能是 `0`。
- `n=2`：只有一条边，`|a_2-a_1|<=a_1+a_2=m`；把全部物品放到任意一端即可达到 `m`。
- `n>=3`：把全部 `m` 个物品放到任意内部格子，其余格子放 `0`。这个格子左右两条边各贡献 `m`，其余边贡献 `0`，总和正好是 `2m`。

因此答案是

\[
ans=\begin{cases}
0,&n=1,\\
m,&n=2,\\
2m,&n\ge 3。
\end{cases}
\]

### 正确性说明

上面的三角不等式证明任何摆法在 `n>=3` 时都不会超过 `2m`；构造 `[0,m,0,...]` 又确实达到 `2m`，所以上界就是最优值。`n=1` 和 `n=2` 分别只有零条和一条边，单独推导也同时给出了上界及达到上界的构造，三种情况均最优。

### 示例演算

- `n=4,m=5`：取 `[0,5,0,0]`，美观度为 `5+5+0=10=2m`。
- `n=2,m=5`：取 `[5,0]`，只有一条边，答案为 `5`，不能误用 `2m`。
- `n=1`：不论 `m` 多大，相邻差的空和都为 `0`。

### 算法步骤

1. 读取一组 `n,m`。
2. 若 `n==1`，答案设为 `0`。
3. 否则若 `n==2`，答案设为 `m`。
4. 否则答案设为 `2*m`。
5. 按题目要求输出各组答案。

### 实现注意

- 不需要真的构造数组，也不需要 DP 或搜索。
- `n,m` 可达 `10^9`，应统一使用 64 位整数，避免中间表达式溢出。
- 多组答案的输出格式以原题为准；算法本身每组相互独立。

### 复杂度

- 时间复杂度：每组 `O(1)`，适合 `n,m` 极大的数据。
- 空间复杂度：`O(1)`。

## q02：字符消除

题目链接：[字符消除](https://www.nowcoder.com/questionTerminal/c2d5576d39bf41e99bbe2f5ac9270889)

### 题意转化与关键观察

每次只能删除当前字符串中相邻的两个字符。字符删除后，原来不相邻的位置可能变成相邻，因此不能只在原串中贪心选择相邻对。

把原串位置画在一条线上，并把最终一起删除的两个原位置连线。两条配对线不可能交叉：若存在 `l<p<r<q`，想让 `l` 与 `r` 相邻必须先删掉中间的 `p`，但 `p` 又要等到 `q` 才能配对，产生矛盾。因此所有删除过程等价于一个“互不相交、允许嵌套”的完美配对，这正是区间 DP 的结构。

### 从删除过程到 DP 转移

令 `dp[l][r]` 表示把原串闭区间 `[l,r]` 完全删除能得到的最大费用；只对偶数长度区间定义合法值，空区间的值为 `0`。

考察区间最左端 `l` 最终和哪个位置 `p` 一起删除：

1. 在 `l` 和 `p` 被删除之前，中间 `[l+1,p-1]` 必须先完全删空，二者才能相邻。
2. 中间长度必须为偶数，因此 `p-l` 必须为奇数，即 `p=l+1,l+3,...`。
3. 删除 `(l,p)` 后，右侧 `[p+1,r]` 与前面的选择互不影响，也独立取最优。

所以有

\[
dp[l][r]=\max_{p=l+1,l+3,\ldots,r}
\bigl(dp[l+1][p-1]+cost(s_l,s_p)+dp[p+1][r]\bigr)。
\]

按区间长度 `2,4,...,n` 递增计算，转移依赖的两个子区间都已求出，最终答案为 `dp[0][n-1]`。

### 正确性说明

对区间长度做归纳。任意合法删除方案中，最左位置 `l` 必有唯一配对点 `p`；非交叉性质保证 `[l+1,p-1]` 和 `[p+1,r]` 分别形成完整、独立的删除方案，因此该方案一定被某个转移枚举到，DP 不会漏掉最优解。反过来，任一转移先按最优方案删空中间，使 `l,p` 相邻后删除二者，再删右区间，确实构成合法过程。因此转移得到的最大值恰好是最优值。

### 示例演算：长度 4

设字符串位置为 `1..4`、字符为 `a,b,c,d`。位置 `1` 只能与 `2` 或 `4` 配对：

- 配对 `(1,2)`：贡献 `cost(a,b)+dp[3][4]`。
- 配对 `(1,4)`：必须先删除 `(2,3)`，贡献 `dp[2][3]+cost(a,d)`。

位置 `1` 不能与 `3` 配对，因为中间只剩位置 `2`，无法被完整删除。`dp[1][4]` 就是上述两个合法结构的较大值。

### 算法步骤

1. 建立 `n*n` 的 64 位 DP 表，并把所有状态初始化为负无穷；约定访问空区间时返回 `0`。
2. 枚举偶数区间长度 `len=2,4,...,n`。
3. 枚举左端点 `l`，令 `r=l+len-1`。
4. 枚举 `p=l+1,l+3,...,r`，计算“中间最优 + 当前配对费用 + 右侧最优”，更新 `dp[l][r]`。
5. 输出 `dp[0][n-1]`。

伪代码骨架：`for len even -> for l -> for p step 2 -> dp[l][r]=max(dp[l][r], left+cost+right)`。

### 实现注意

- 费用矩阵有方向：原位置始终保持相对次序，所以使用 `cost(s[l],s[p])`，不能把两个字符交换。
- 若矩阵允许负费用，合法状态必须从负无穷开始；用 `0` 初始化会错误地允许“什么都不删”。
- 空区间（如 `p=l+1` 时的中间部分、`p=r` 时的右侧部分）贡献为 `0`。
- `n<=500`，总费用及负无穷哨兵使用 64 位整数，做加法前避免让哨兵参与溢出。

### 复杂度

- 时间复杂度：`O(n^3)`；`n<=500`，只枚举偶数区间和合法奇偶配对点。
- 空间复杂度：`O(n^2)`，约保存 `250000` 个 64 位状态。
